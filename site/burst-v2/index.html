New · Nagi Burst V2 · SDK v0.7.0

Write the rules.
Get the decision.

Nagi Burst V2 decides for small machines that you describe in the Nagi machine language. An exact reader turns your text into the machine, an exact lookahead simulates it, and a 3.10M-parameter learned core proposes a prior where the search cannot tell moves apart. Numpy only, one CPU thread, no GPU.

On unseen machines, V2G's success comes mainly from exact lookahead on the given rules, which on small machines covers much or all of the reachable state set. The learned core did not measurably add to that lookahead (claim G+ not shown), so we do not claim that learning generalizes.

What we claim

  • Every must-pass release gate passed in one frozen, sealed run, and an independent recount of every number from the raw receipts matched (MATCH).
  • On unseen machines written by separate authors (48 families, 16 domains), mean success is above 0.60 under the preregistered test: θ̂ = 0.854, Holm-matched lower bounds 0.746 (family) and 0.681 (domain). Claim NS is shown.
  • Against Nagi Burst V1 on the same sealed Arena seeds, V2 won every pairing it did not tie: win share W 1.000 on Snake Rush, 1.000 on Rotorwash-Ramp and 0.979 on Booster Gauntlet, where it landed 23 of 24 rounds and V1 landed none.
  • Each decision fits the latency gate on one Apple M2 thread: the largest p95 upper bound is 50.8 ms against a 200 ms limit.
  • The text path gives exactly the decision of the structured path: 0 mismatches in 7,506 requests.

What we do not claim

  • That learning generalizes to unseen machines. Claim G+ is not shown: the core minus the same search is −0.003 (Holm p 1.000).
  • North-star attainment. The test machines are small (median 922.5 reachable states). On the subset where the lookahead saw least, success is 0.730 and NS is not shown there (lower bounds 0.485 / 0.398).
  • Strength on every kind of machine. On Rotorwash-like unseen machines success is only 0.484 (descriptive).
  • Reading rules written in plain English. The prose reader got 23 of 48 rulebooks exactly right, so gate R failed and the reader moves to V2.1.
  • Generalization on the Arena games: the core was trained on all three, so they are seen tasks.
  • Any comparison beyond Nagi Burst V1. The release gates compare V2 with V1 only; Jev appears only in the Game Arena section, under the labels given there.

01 / Use it

Install. Describe. Decide.

Burst V2 ships in the Nagi SDK v0.7.0 as the module nagi.burst2. The core is one small numpy file. It downloads from Hugging Face at a revision pinned in the SDK and is checked against its sha256 before use.

# the SDK (module nagi.burst2), pinned to this release
python -m pip install "nagi-decisions @ git+https://github.com/nagisanzenin/nagi.git@v0.7.0"

Write the machine as text, then ask for a decision. The quickstart from the README:

from nagi.burst2 import load_core, operate

RULES = """machine mz-1
vars:
  x in [0, 6], start {3}, out of range: clamp
controls:
  @m: DEC -1, KEEP 0, INC 1
random $w: none
rules (in order, each tick):
  1. x := x + @m
crash if any holds:
  1. all(x <= -1)
goal: all(x == 6)
"""
core = load_core()   # nagisanzeninz/Nagi-Burst-V2, pinned revision, sha256-checked
out = operate(RULES, {"x": 3}, {"core": core, "session": "episode-1", "step": 0})
print(out["choice"], out["probabilities"])   # {'m': 'inc'} {'m': {'dec': 0.0, 'keep': 0.0, 'inc': 1.0}}

Three parts, all exact except the prior

  1. Reader. Parses mz-1 text (integer variables, controls with DEC / KEEP / INC options, ordered rules, an optional random input, crash conditions, a goal) into the exact machine. mz-1x adds reply delay, hidden variables and a history window. Invalid programs are rejected, never guessed.
  2. Lookahead. Simulates the parsed machine itself: 100,000 simulations per decision, horizon up to 40, with belief tracking when variables are hidden or controls are delayed.
  3. Learned core. Reads the program structure and proposes a prior. It is used only inside the set of moves the search cannot tell apart, and only when its confidence is at least 0.6.

The output is {"choice", "joint", "probabilities", "joint_probabilities", "stats"}. The defaults are the released configuration; changing them gives a configuration that was not evaluated. Pass a session and an increasing step to make every draw replayable.

Example: a delivery robot

Your own game stays your own code; Nagi only needs its rules. A robot on a small grid must pick up a parcel and deliver it before its battery runs out, and standing on a charger adds battery. With these rules and session robot-1, Nagi delivers after 9 ticks.

machine mz-1
vars:
  x in [0, 4], start {0}, out of range: clamp
  y in [0, 4], start {0}, out of range: clamp
  battery in [0, 10], start {8}, out of range: clamp
  parcel in [0, 1], start {0}, out of range: clamp
controls:
  @dx: DEC -1, KEEP 0, INC 1
  @dy: DEC -1, KEEP 0, INC 1
random $w: none
rules (in order, each tick):
  1. x := x + @dx
  2. y := y + @dy
  3. battery := battery - abs(@dx) - abs(@dy)
  4. if all(x == 4, y == 0): parcel := 1
  5. if all(x == 2, y == 2): battery := battery + 4
crash if any holds:
  1. all(battery <= 0)
goal: all(parcel == 1, x == 0, y == 4)
  • It found the charger stop. At tick 6 it waits on the charger (battery 4 → 8). No rule says "wait": the lookahead saw that every way home would otherwise crash.
  • It plays for the goal, not for battery. At tick 0, 3 moves tie and the draw steps into the wall; leftover battery is not part of the goal.
  • No way to win: it stops instead of crashing. Without the charger rule no goal is reachable (116 reachable states, none a goal). All 9 joint moves tie at the no-goal value −33.1, it drifts while moving is safe, and from tick 6 it stands still.

03 / The research

Search does the generalizing.

Two research claims were preregistered next to the gates and tested together with a Holm correction. NS asks whether mean success on unseen machines is above the north-star level. G+ asks whether the learned core adds anything to the same lookahead at the same latency cap; the comparator is the same search with no core and a slightly larger simulation budget.

NS holds, G+ does not. The reason is coverage: on machines this small the lookahead sees much or all of the reachable state set, so there is little left for a learned prior to decide. The binding release sentence says exactly that:

Descriptive checks

  • Leak check · descriptiveZoo-Unseen-D minus the development set Zoo-Dev-L: −0.031 (lower bound −0.156) → no flag, so gate G stands.
  • Zoo-Unseen-C · descriptiveA second unseen set (16 families / 4 domains): θ̂ 0.893; Δ̂+ +0.012 (lower bound −0.013). Learning is not shown there either.
  • Prose path · descriptiveWith the frozen prose reader in front, G would be 0.469: −0.385 per family against the exact parser (lower bound −0.517). That is why the reader moves to V2.1.

What comes next

  • V2.1: the prose reader. Close the gap between how people write rules and the training prose, and add an adapter for external LLM readers, so plain-English rulebooks can be used.
  • Large machines. The open research question is machines too large or too long for the lookahead to cover. That is where a learned core has to earn its place, and where G+ must be tested next.
  • Rotorwash-style control. Closed-loop (DAgger) training for the Rotorwash game head is next in the backlog.

Disclosures carried into every public text: the binding sentence above; the core was trained on the three Arena games; the unseen test machines were written by Claude Opus agents separate from the training authors and checked by blind review and an exact oracle; the prose reader is deferred to V2.1 with its R result reported; the release gates compare with Nagi Burst V1 only; a Booster round is its first hop; Arena play used the nominal one-tick reply, justified by gate L. Total cloud spend for all of Burst V2: $25.16 (billed); the frozen evaluation itself: $0.20.

05 / Can and cannot

Know the edges.

  • CanDecide every tick for a small machine you can write in mz-1 or mz-1x: discrete controls, integer state, random inputs, reply delays and hidden variables, with a visible probability for every option.
  • CanRun on one CPU thread with numpy only (on the measured Apple M2 it stays inside the latency gate), and replay every draw exactly when you pass a session and a step.
  • CanTell you how much it saw: stats["exhausted"] and stats["visited"] report how much of the machine the lookahead covered for each decision.
  • Cannot yetRead rules in plain English. Write the machine language; the prose reader comes in V2.1.
  • CannotPlan for a rule you left out. The decision is only as good as the machine you wrote.
  • Not shownLarge machines. Bigger machines run, but the lookahead sees less of them, and that regime was not tested: the sealed set had 0 families with machines larger than the search budget.
  • Not measuredLatency on other hardware than the Apple M2 serving class above.
